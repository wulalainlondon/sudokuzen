# W1 需求凍結與驗收標準

版本：W1
參考來源：`progress.md`、`TODO.md`
更新日期：2026-04-10

## 1. W1 目標與非目標

W1 的目標是把目前 `TODO.md` 中仍未完成的兩個使用者可見能力收斂成可驗收、可交付的範圍，並維持現有數獨主流程穩定不回退。W1 只處理「回放可視化」與「右上角最高技巧顯示」這兩個功能的最小可交付版本，不擴大到新玩法、新關卡系統或解題引擎重構。

W1 的非目標是新增新的解題技巧、調整關卡生成策略、改造排行榜系統、重新設計整體 UI 主架構，或把其他延後需求一併納入。本階段不追求功能面的大擴充，只要求把剩餘兩項 TODO 做到可用、可測、可驗收。

## 2. In Scope / Out of Scope

### In Scope

1. 回放功能的可視化呈現。
2. 右上角顯示目前關卡的最高技巧。
3. 回放與最高技巧顯示在桌機與手機版面都可讀、可操作，且不遮擋核心遊戲區。
4. 針對上述兩項功能補上必要的驗收測試或手動檢查步驟。
5. 若需要新增文案、空狀態、錯誤狀態，僅限於上述兩項功能的呈現。

### Out of Scope

1. 新增或更改 Sudoku 核心規則、解題演算法、關卡內容與難度分佈。
2. 新增排行榜、首通榜、成就、商店、登入流程或帳號系統。
3. 重新定義 replay 資料來源以外的歷史資料結構。
4. 全站視覺重設、跨頁導航改版或主遊戲畫面之外的版面重構。
5. 對現有已完成功能做行為變更，除非是為了讓本 W1 功能能正確展示。

## 3. 兩個未完成功能的驗收條件

### 3.1 回放可視化

回放可視化的 W1 定義：玩家完成一局後，系統能把這局的解題過程以逐步、動態、可辨識的方式呈現出來，讓使用者看得出每一步的盤面變化。

#### Scenario A: 完局後可進入回放

**Given** 玩家已完成一局遊戲，且系統已有該局的回放資料或可重建的操作序列  
**When** 玩家點擊「回放」或等價入口  
**Then** 系統應開啟回放畫面或回放面板，並開始顯示這一局的步驟

#### Scenario B: 回放過程可視化

**Given** 回放已開始播放  
**When** 系統播放到任一步驟  
**Then** 畫面應清楚標示本步驟所影響的格子、數字變化或刪除變化，且使用者能看出目前進度

#### Scenario C: 回放可正常結束

**Given** 回放播放到最後一步  
**When** 回放結束  
**Then** 系統應停在結尾狀態，且使用者可重新播放或離開回放，不應卡死、閃退或丟失已完成的盤面結果

### 3.2 右上角最高技巧顯示

右上角最高技巧顯示的 W1 定義：在遊戲畫面右上角，玩家可以直接看到目前關卡所需的最高階解題技巧，且此資訊與該關卡一致。

#### Scenario A: 進入關卡即顯示技巧

**Given** 玩家進入任一關卡  
**When** 關卡畫面完成載入  
**Then** 右上角應顯示該關卡的最高技巧名稱，使用者不需要額外點擊才能看到

#### Scenario B: 顯示內容與關卡一致

**Given** 某關卡已定義其最高技巧標記，或系統可從關卡資料計算出最高技巧  
**When** 玩家查看右上角技巧標示  
**Then** 顯示內容應與該關卡實際定義一致，且不可誤顯為更低或更高的技巧層級

#### Scenario C: 資料缺失時有安全降級

**Given** 某關卡暫時缺少最高技巧資料  
**When** 玩家進入該關卡  
**Then** UI 應顯示可理解的 fallback 文案，不可讓右上角區塊破版、空白到無法判讀，或影響遊戲操作

## 4. Definition of Done

W1 視為完成，需同時滿足以下條件：

1. `TODO.md` 中的「回放 可視化」與「右上角顯示關卡所需最高技巧」已完成，或已被替換成新的、等價且更明確的完成定義。
2. 兩個功能都能在主要目標裝置上正常運作，且不遮擋、不破壞現有遊戲流程。
3. 至少有一組可重複執行的驗收方式，能確認回放與技巧顯示的核心行為。
4. 若功能需要資料來源、格式或 fallback 文案，相關規格已落地且不依賴口頭共識。
5. 相關程式碼已完成基本自測，且沒有引入已知阻塞性的錯誤。
6. 本文件所列 PM 待決項有明確結論，避免工程端自行猜測。

## 5. 需要 PM 決策的項目

1. 回放的產品形態：是獨立回放頁、彈窗、側欄，還是直接在通關畫面內播放。
2. 回放控制範圍：W1 是否只需要自動播放，或必須提供暫停、單步、拖曳進度條。
3. 右上角最高技巧的資訊來源：以關卡 metadata 為準，還是以 solver trace / 實際驗證結果為準。
4. 最高技巧的 fallback 文案：當資料缺失時要顯示什麼字樣，以及是否要隱藏該欄位。
5. 技巧名稱的產品文案：採用技術名詞原文、中文譯名，或雙語顯示。
6. 兩項功能的優先順序：若排期不足，先完成哪一項，以及是否允許分階段交付。
7. 是否需要把這兩項功能納入正式 QA 驗收清單，或只作為開發完成標準。
